## Done — reply bundle built, cross-checked and published

**8 customer reply templates**, each with greeting, ordered technical steps, KB/doc references, empathetic closing, internal handling notes and per-claim source citations:

2. Sync connectivity / files reaching only some users — SYNC-401, policies, index

Plus `reference/quick_answers.md` (9 short answers: domain verification, selective-sync regex, webhooks, scheduling, region latency, 503 vs 429, >5 GB uploads, APAC locales, upgrade paths), a consistency review, source inventory, and email-thread analysis.

### Cross-check findings (the main value-add)

The sources contradict each other in ways that would produce wrong customer statements. Eleven findings are documented with severity, evidence and fix; the four critical/high ones:

- **C1 — `TKT-2024-018` is two different tickets** (Stark sync outage vs Stark audit export, same customer/date, different agents). Templates warn against citing the ID alone.
- **C2 — `v3.3.2` conflict**: email promises it as an index-migration release; internal material describes an emergency security release; changelog has no 3.3.2 entry. Templates deliberately avoid naming it.
- **C3 — index-format change misattributed to 3.3.0**: 3.3.0 release notes don't mention it; a v3.2 ticket does.
- **C4 — three incompatible CLI forms** for index/agent operations (`index rebuild` vs `index clear` + `--index-rebuild-priority`, `cloudsync stop` vs `cloudsync agent stop`).

Also flagged: plan/tier taxonomy (`Premium` vs Professional/Enterprise vs platinum-plus), relay-region lists, draft v3.4 notes beside released ones, RELAY-042 region mismatch, wrong `related_kb` mappings, Android fix version.
