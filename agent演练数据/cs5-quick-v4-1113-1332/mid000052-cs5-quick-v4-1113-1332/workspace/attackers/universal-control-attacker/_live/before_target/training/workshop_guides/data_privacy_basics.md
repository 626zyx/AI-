# Data Privacy Basics for New Hires

## Training Workshop Guide — Facilitator Edition

**Duration:** 60 minutes
**Format:** In-person or virtual (Zoom)
**Audience:** All new hires (required within first 2 weeks)

## Learning Objectives

By the end of this session, participants will be able to:
1. Identify what constitutes personal data under GDPR and CCPA
2. Classify data according to the company's Data Classification Policy
3. Apply the principle of data minimization in daily work
4. Recognize common phishing and social engineering attempts
5. Know where to report a suspected data incident

## Session Outline

### Part 1: What is Personal Data? (10 min)

**Facilitator notes:** Use the slide deck to walk through the definition. Emphasize that "personal data" is broader than PII — it includes IP addresses, device IDs, and behavioral data.

Key examples to show:
- Name + email address: YES — personal data
- Customer purchase history: YES — personal data
- Aggregated department headcount: NO — not personal data
- Anonymized survey results: NO — provided no re-identification possible

### Part 2: Data Classification (15 min)

The company uses three classification levels:

| Level | Label | Examples |
|-------|-------|----------|
| Public | Green | Marketing materials, job postings, public documentation |
| Internal | Yellow | Team wikis, project plans, onboarding guides, meeting notes |
| Confidential | Red | Customer data, employee records, financial results, security reports |

**Activity:** Distribute the classification worksheet (Appendix A in participant guide). Ask participants to classify 10 sample data items. Review as a group.

### Part 3: Data Minimization (10 min)

Three rules:
1. Collect only what you need
2. Keep only as long as needed (follow retention schedules)
3. Share only with those who need it (need-to-know principle)

**Common mistake:** "I'll CC the whole team just in case" — every recipient is a potential data leak vector.

### Part 4: Phishing Awareness (15 min)

**Red flags to teach:**
- Urgent language ("Your account will be disabled!")
- Sender address that looks almost right (microsoft-support@outlook.com)
- Unexpected attachments or links
- Requests for credentials or MFA codes

**Activity:** Show 5 real-world phishing examples (slides 22-26). Ask participants to identify the red flags.

### Part 5: Reporting a Data Incident (10 min)

If you suspect a data incident:
1. **Do NOT delete or modify anything** — preserve evidence
2. **Report immediately** via one of these channels:
   - Email: security@company.com
   - Slack: #security-incident channel
   - Phone: 1-800-555-SECURITY (24/7 hotline)
3. **Do NOT discuss externally** until the security team provides guidance
