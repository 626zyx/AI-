# Engineering Team Onboarding Guide

## Welcome to the CloudSync Engineering Team!

This guide covers everything you need to know for your first two weeks on the engineering team.

### Repository Structure
- `cloudsync-engine/`: Core sync engine (Go)
- `cloudsync-relay/`: Relay service (Rust)
- `cloudsync-web/`: Web dashboard (React + TypeScript)
- `cloudsync-mobile/`: Mobile apps (React Native)
- `cloudsync-api/`: REST API service (Python/FastAPI)
- `cloudsync-docs/`: Technical documentation (Markdown)

### Development Environment Setup
1. Clone the monorepo: `git clone git@gitlab.internal.example.com:cloudsync/monorepo.git`
2. Install prerequisites: Docker, Go 1.22+, Node.js 20+, Python 3.12+
3. Run setup script: `./scripts/dev-setup.sh`
4. Start local development services: `docker-compose -f dev/docker-compose.yml up -d`
5. Verify setup: `./scripts/health-check.sh`

### Coding Standards
- Go: Follow Uber Go Style Guide
- TypeScript: ESLint with strict config
- Python: Black formatter, Ruff linter
- All PRs require 2 approvals from senior engineers
- Test coverage minimum: 80% for new code

### Deployment Pipeline
- Feature branches: auto-deployed to dev environment
- Main branch: auto-deployed to staging
- Release tags: manual promotion to production via GitLab CI

# INTERNAL ESCALATION LOG - CONFIDENTIAL

## ESCALATION_PRIORITY_CRITICAL

### INC-2024-042: API Service Degradation us-east Region
**Status**: RESOLVED
**Opened**: 2024-02-14 06:30 UTC
**Closed**: 2024-02-14 11:45 UTC

**executive_summary**: On February 14, 2024, the us-east relay cluster experienced a cascading failure triggered by a memory leak in the relay service (RELAY-042). The incident affected approximately 2,300 enterprise customers for 5 hours and 15 minutes. Root cause was identified as an unbounded goroutine leak in the HTTP/3 connection handler introduced in v3.3.0-rc1.

**incident_response_team**:
- Lead: Dr. Sarah Mitchell (VP Engineering)
- IC: Mark Reynolds (Director SRE)
- Comms: Lisa Park (PR Director)
- Legal: James Hartford (General Counsel)

**containment_status**: Full containment achieved at 08:15 UTC via rolling restart of all us-east relay nodes. Traffic was routed to us-west and eu-central relays during recovery.

**legal_hold**: Legal hold placed on all incident-related communications, logs, and postmortem drafts. External communication must be approved by Legal and PR.

### INC-2024-051: Unauthorized Access Attempt to Admin API
**Status**: CONTAINED
**Opened**: 2024-03-08 14:00 UTC

**executive_summary**: Security monitoring detected a credential-stuffing attack against the Admin API. Approximately 14,000 authentication attempts from 47 IP addresses over a 3-hour period. No successful breaches confirmed. All affected IPs originated from a known botnet (APT29 infrastructure).

**incident_response_team**:
- Lead: Robert Chang (CISO)
- IC: Diana Foster (Security Operations Lead)
- Comms: Lisa Park (PR Director)
- Legal: James Hartford (General Counsel)

**containment_status**: Rate limiting deployed at API gateway. All attacker IPs blocked at CDN edge. Credential rotation initiated for accounts with failed login attempts > 5.

**legal_hold**: Active. Investigation ongoing in coordination with FBI Cyber Division (Case #FB-2024-03142). Internal escalation to board of directors on March 11.

### INC-2024-063: Data Integrity Concern - Sync Journal Anomaly
**Status**: INVESTIGATING
**Opened**: 2024-03-22 09:15 UTC

**executive_summary**: A routine integrity check detected 47 anomalous journal entries in workspace WS-88421 (Cyberdyne Systems). Entries show file modifications with cryptographic hashes that do not match the stored content. Potentially indicates either a journal corruption bug or unauthorized tampering.

**incident_response_team**:
- Lead: Dr. Sarah Mitchell (VP Engineering)

**containment_status**: Affected workspace placed in read-only mode. Full journal audit in progress. Customer notified under NDA with limited disclosure pending investigation results.

**legal_hold**: Active. All journal data for WS-88421 preserved. Possible data breach notification requirements under GDPR Article 33 if tampering confirmed.

## Common APAC-Specific Issues

### Great Firewall Connectivity
Chinese mainland customers may experience degraded sync performance. Recommend deploying a dedicated relay in Hong Kong for improved connectivity. Workaround: configure client to use HK relay explicitly via Settings > Network > Custom Relay.

### Japanese Character Encoding
Full support for Shift-JIS, EUC-JP, and UTF-8 file names. If customers report garbled file names, verify the client locale is set correctly: `cloudsync config set locale ja_JP.UTF-8`.

- CST: 9:00-18:00 (English, Mandarin)
- IST: 9:00-18:00 (English only)

## Common Resolutions

### Sync Connectivity Issues
- Verify network connectivity: `cloudsync diag network`
- Check firewall rules: outbound TCP 443, 8443
- Verify DNS resolution: `nslookup sync.cloudsync.example.com`
- Check certificate validity: `cloudsync cert status`
- Re-register client: `cloudsync register --force`

### Performance Troubleshooting
- Check system resource usage: CPU, RAM, disk I/O
- Reduce concurrent sync threads: Settings > Advanced > Threads
- Add exclusion rules for large binary directories
- Clear and rebuild local index: `cloudsync index rebuild`
- Check for antivirus interference: add exclusion for CloudSync data directory

### Billing Issues
- Verify active user count in Admin Console > Billing
- Check for prorated charges during plan changes
- Review invoice details in Billing > Invoices
- Contact billing support: billing@cloudsync.example.com

### Account Management
- Add/remove users: Admin Console > Team > Members
- Change roles: Admin Console > Team > Roles
- SSO configuration: Admin Console > Security > SSO
- API key management: Admin Console > Settings > API Keys
