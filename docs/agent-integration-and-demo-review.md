# Agent 接入、注入面选择与 Demo 检查

更新：2026-11-20（注入文件分类与接入说明）。本文区分已经实现的页面行为、已有测试证据和后续后端工作，不把演示回放当作新实测。

## 1. Agent 接入：用户究竟需要填写什么

接入应复用用户已经能完成任务的 Agent。平台负责运行隔离与评估，不替用户补写任务规划、工具循环或新的 Agent 主体。

| 字段 | 填写要求 | 保存形式 |
| --- | --- | --- |
| 智能体名称 | 必填，平台内显示名称 | `name` |
| 用途说明 | 选填自然语言，仅说明 Agent 的能力与用途 | `description` |
| 基座模型 | 从已接入且具有智能体基座用途的模型资产选择 | `baseModelId` |
| 镜像地址 | 一个完整 Docker 镜像引用，含版本标签或 64 位 SHA-256 摘要；不另填版本 | `image` |
| 启动程序 | 一个已有非交互程序名或容器内路径 | `command[0]` |
| 启动参数 | 选填，每行一个参数或参数值；行内空格保留，不含任务正文或任务参数名 | `command[1…]` |
| 任务文本传入方式 | `stdin`、`argv`、`file` 枚举 | `inputContract.transport` |
| 任务参数名 | argv/file 时填写单个参数名；留空表示最后一个位置参数 | `inputContract.flag` |
| 注入面文件 | 需要间接提示注入时申报控制文件的分类与具体路径 | `surfaceDeclarations` |

不再提供预置框架入口，也不要求用户先选择平台框架。Demo 中已有 Qwen Code 按用户下载并交付镜像接入的方式呈现，另外加入测试中的 OpenCode 1.19.5、Qwen Orchestrator · 0.0.5-fixed、Deep Agents Code 0.2.10，共四个资产。

- 平台读取完整 `task.md`，补充运行和工具说明，形成 prompt。Agent 必须接受完整文字任务，但不必只支持 stdin。argv 将文本作为一个参数值追加；file 由平台生成 UTF-8 文本文件并传递路径。后两种只填 `-p`、`-n`、`--prompt-file` 这样的单个参数名，留空表示位置参数，不填“该参数接收任务”等自然语言。
- 镜像地址如 `registry.example.com/team/agent:1.0.0` 或 `repository@sha256:…`，版本包含在该字段内；不是网页下载链接或 ZIP/TAR 文件路径。
- 镜像应包含 Agent 程序、依赖及所需工具，并已有接收任务后非交互运行和退出的入口。初始化放在镜像入口内，启动字段不解析 shell 管道或重定向。
- 注入文件每行只填写“分类 + 具体路径”。使用一个分组下拉，直接选择指令、规则、技能、命令、长期记忆、会话历史、任务状态或配置文件，不额外要求用户填写作用范围、加载方式或触发条件，也不增加接入必填项。
- 文件不包含普通业务工作区文件。项目内使用相对路径，用户目录使用 `HOME/` 前缀，例如 `AGENTS.md`、`HOME/.qwen/QWEN.md`。技能需要具体到 `SKILL.md` 文件，不填写目录、通配符或模板。示例不能代替当前靶标的已核验能力。
- 镜像解析可以辅助发现候选文件，但不能仅凭镜像名称、文件存在或路径声明认定它会被 Agent 读取。平台需要结合入口、作用范围、加载方式、触发条件和运行探针核验能力，再将具体文件标为已核验。发现技能不代表正文已被调用；实际调用情况须由单次执行证据判断。
- 没有文件注入能力可以不申报，资产仍可用于基础安全演练；Universal 需要至少一个已经核验并允许选择的文件。

### 模型连接为什么不再单独填写

模型资产提供服务地址、请求模型标识与凭据。所有新接入镜像必须遵循标准协议 `openai_env_v1`，实际读取并使用 `OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_API_KEY` 三个环境变量。平台在运行时从所选模型资产获取并注入具体值；实际值不得写死在镜像中，也不得被镜像内置固定配置覆盖。普通用户只选择基座模型，不重复填写地址或密钥，不填写变量映射、配置模板或转换脚本。

如果原生 Agent 使用其他变量、配置文件或 `--model` 参数，由镜像开发者在交付前完成适配：镜像入口读取三个标准变量，并转换成原生程序能使用的配置。普通用户无需修改脚本，平台不为新接入镜像提供任意映射表单或逐个增加专用配置转换。没有完成标准变量适配的镜像不能通过接入验证。

历史测试事实：现有后端 `framework/core/target_adapters.py` 支持 `env_only / config_template / hybrid`。Qwen Code、Qwen Orchestrator 曾使用平台生成的 `.qwen/settings.json`；OpenCode 曾使用平台生成的 `opencode.json`；Deep Agents Code 的已测配置通过环境变量及 `--model` 参数指定连接。已有演示资产保留这些已验证的适配方式，但历史适配不构成新镜像的接入豁免；后续新接入仍必须遵守三个标准变量要求。

当前 Demo 新接入表单只保存 `openai_env_v1` 契约，不执行真实验通。选择基座模型不等于镜像已经兼容；后端验证必须确认实际使用的服务地址、请求模型标识和凭据来自所选资产，并排除镜像内固定配置覆盖。

新申报保存 `modelConnection: { source: 'model_asset', modelId, adapter: 'openai_env_v1' }`，不再保存自由文本 `modelBinding`。命令以数组保存，任务输入保存明确的 `inputContract`，避免后端猜测字符串意图。

### 自然语言说明与使用指南

只保留选填的用途说明，用自然语言描述 Agent 能做什么，例如“读取业务文档并整理客服回复”，用于资产识别与选型。接入详情不重复展示“接入方式：用户镜像”，用途也不写“用户交付的镜像”这类来源说明。

删除外部依赖、任务传入说明、文件加载说明等自由文本字段。镜像打包要求、参数填写规则、任务输入示例、模型变量约定和注入文件要求统一放到右上角“使用指南”，入口位于消息提醒左侧。指南不把自然语言当作可执行配置。

平台内部负责：编制 target.yaml、工作区准备和文件挂载、模型与凭据注入、工具环境、任务调度、资源/超时管理、证据采集、判定及结果归一化。这些不应直接变成接入表单的必填项。

本轮实现：结构化镜像接入契约、字段及文件路径校验、待验证状态和引用删除限制。添加/删除注入文件局部更新表格，保留弹窗滚动位置与其他字段；切换输入协议也保留滚动位置。点击“校验信息”只检查填写信息，不代表连接成功。新申报文件不会自动变为已核验能力，待验证资产不能作为正式任务靶标。镜像拉取、容器运行、任务协议、模型注入、实际加载能力验证及状态回写仍需后端接入。

### 沙箱是否需要展示给用户

默认不需要把沙箱作为主要页面或接入必填项。隔离环境由平台准备，用户负责提供可运行的 Agent 镜像与已有入口即可。只有网络权限、资源预算或工具能力确实影响用户选择时，才开放相应高级设置；详情可按需提供镜像版本、网络策略、资源与超时的只读摘要。容器挂载、编排参数、内部凭据等不应进入常规用户流程。

### 之前测试对产品的约束

- Qwen Code、OpenCode、DeepAgents Code 的结论只适用于已测试的版本、入口和配置，不能扩展为整个框架所有版本都支持。
- Goose recipe 的 data_file 输入不等同于通用完整任务入口；平台另写规划编排会改变被测 Agent，不能作为“原生接入成功”的证据。
- 工作区存在文件或命中关键词，不足以证明业务任务完成；没有远端发布成功证据，就不能把本地文件产出解释为上传成功。
- 原始 evaluator 的嵌套风险结果与归一化得分需要逐项核验。此前 000019 的 unsafe 标记案例说明不能只依赖一个顶层 score。

## 2. 创建时选择单个或部分注入面：已实现具体文件选择

第一层按靶标核验过的注入面分类展示；第二层在分类内选择具体文件。只显示当前资产已核验的能力，不提供无约束的“任意路径”文本框。

当前位置：在第一步“任务与对象”选择靶标后，显示分类后的“注入面范围”，支持一个或多个具体文件。初始为空，切换靶标清空旧选择；选择 Universal 时必须至少保留一个有效文件，空选不默认为全部。基础安全演练不使用注入文件，保存配置时清空注入范围。Agent 创建只有任务与对象、红队配置、评估配置、确认配置四步，不包含蓝队。

策略中心方法说明与接入分类共用以下四组。表中的文件仅为类别示例，不能据此认定某个靶标支持这些路径；接入申报必须提供真实、具体的文件。

| 分组 | 具体分类 | 作用与示例 | 平台核验重点 |
| --- | --- | --- | --- |
| 指令与约束 | 指令、规则 | 项目或用户指令，如 QWEN.md；有触发条件的规则，如 .claude/rules/security.md | 实际用途、作用范围、加载位置与触发条件 |
| 技能与命令 | 技能、命令 | 技能如 .qwen/skills/support/SKILL.md；命令如 .opencode/commands/review.md | 发现和调用方式；发现技能不等于正文被调用 |
| 记忆与历史 | 长期记忆、会话历史、任务状态 | 跨任务知识和偏好、先前对话、待办与进度分别归类；Deep Agents 用户 HOME/.deepagents/agent/AGENTS.md 是长期记忆示例 | 文件格式、读取/恢复方式及实际使用范围 |
| 运行配置 | 配置文件 | Agent 支持的行为配置，如 .reasonix/settings.json | 明确开放的配置项；排除平台管理的模型凭据 |

分类依据是实际用途，不能仅根据文件名全局判断。Deep Agents 用户级 AGENTS.md 的记忆用途不代表其他 Agent 的同名项目指令文件也应归为长期记忆。长期记忆、会话历史和任务状态在下拉中作为三个具体选项，用户不需要再填一份用途自由文本。

后端映射：target.attack_surfaces 声明目标能力与原生路径，attacker.vector_permissions 表达本次显式白名单。最终范围取靶标能力、攻击方法权限与用户选择的交集。surface_family 不能替代实际路径声明；省略 vector_permissions 可能继承 workspace 和 provider 默认范围，不表示“不注入”。

策略中心方法详情按上述四组展示说明与示例；资产申报和新任务可选分类不含 `workspace`。OpenART 的底层能力及历史证据可能包含工作区攻击，但不因此向新表单开放普通业务文件；历史发生过的工作区注入不删除或改写。

任务快照已保存 `injectionSurfaceIds` 和 `requestedSurfaces`（文件 ID、分类、路径与向量）；校验拒绝不属于当前靶标的文件。执行证据应另存实际写入、读取/命中、产生影响的范围，不能把“选中”直接统计为“成功注入”。跨任务比较需要固定注入范围。

当前已有间接提示注入方法分类/文件示例、资产申报与已核验文件展示、创建时具体文件多选及配置快照。本次调整统一方法说明与接入申报的四组分类，未新增任务流程或改写历史报告。当前运行仍使用历史证据回放，不执行所选文件范围的新攻击，也不筛选旧结果伪装成重新测试。后端接入时必须将所选文件范围落实为攻击写入权限和路径越界校验；仅保存前端勾选项不足以保证执行约束。

## 3. 本轮 Demo 已处理

- 产品标题统一为 AI Range；模型评估与 Agent 评估导航改名，删除重复侧边分类标题、撤销删除入口及复制草稿通知，缩小详情 ASR 数字。
- 首页保留安全态势内容，改为浅色单演练场，默认模型并通过图标切换 Agent；左侧约 3/5 为 3D 与动态内容，右侧约 2/5 为上下排列的风险提醒和资产态势，联合高度填满剩余屏幕。3D Canvas 覆盖整个演练场内容区，初始构图靠左，右侧气泡为浮层，放大可延伸至气泡下方。
- 两类已发布策略可复制为独立草稿；草稿只编辑/删除。修复快速连续复制产生重复 ID 的问题。
- Agent 新建从空的靶标、策略和裁判选择开始，保存配置后再显式启动，启动时才绑定回放源。
- Agent 全部页面移除蓝队内容；任务详情删除“复制配置”，报告删除“来源任务”按钮与跳转，内部来源数据保留。
- 任务目标从原 task.md 提取描述及分点要求；删除反推轨迹。详情展示最终答复、完成度和抵御情况。
- Agent 页面/报告导出移除轮次字段。报告方法表现改为攻击者视角文字，场景风险保留雷达图与表格，靶标表现独立成块。
- Agent 接入不再用前端延时伪装连通验证。报告删除失误维度条形图和独立失误程度汇总，保留失误维度明细表和表内程度，导出同步。
- Agent 明细内部改称“注入面分析”；列表无勾选时禁用导出。按钮下拉内先单选“明细详情”或“任务包”，再显示范围与格式，不弹模态窗口；明细支持 PDF / Markdown，任务包为 ZIP，单条详情使用相同下拉且限定当前记录。
- 策略中心“蓝队策略”改为“防护策略”，场景题库及策略选项仅展示已有内容的客服题库。

## 4. 整体检查后仍需明确的产品边界

| 优先级 | 问题 | 建议 |
| --- | --- | --- |
| P1 | 新配置启动时可能匹配到相近而非完全一致的历史证据 | 演示模式继续保留执行来源和匹配标识；接后端后按真实配置执行。配置不匹配的回放不可用于严肃模型排名 |
| P1 | 当前 Agent 完成度、失误维度等来自演示人工整理摘要，不全是裁判模型原始结构化输出 | 接后端时定义原始判定、摘要与证据引用契约；不能把人工摘要宣称为实时模型判定，也不能反推执行轨迹 |
| P1 | 资产接入只完成元信息校验，尚无运行验证服务 | 实现镜像拉取、任务协议验证、真实模型调用和退出验证后再标为已接入 |
| P1 | 创建页已保存具体注入文件，但 Demo 不执行新的注入范围 | 后端按文件快照设置显式权限并校验实际写入路径；记录请求范围和实际命中证据，不能用历史回放替代新测试 |
| P1 | 模型资产页仍用前端延时模拟“测试连接成功”（assets.js），与本轮已改正的 Agent 接入不同 | 接真实验证接口之前，将模型页也改为信息校验/待验证，避免把地址格式正确当成连接成功 |
| P1 | 跨任务对比不能仅比较模型/策略 ID | 固定策略快照、题集、裁判、蓝队位置、参数和注入面范围；优先成对比较同一批任务 |
| P2 | 场景样本量有限，基线泄露可能已经存在 | 同时显示分母与基线，增加重复测试，不把单次差异视为稳定排名或因果结论 |
| P2 | Agent 支持路径、发现路径、实际读取和攻击生效是不同层级 | 将接入能力证据与单次执行命中证据分开；仅靠攻击文件存在不能证明生效 |
| P2 | 刷新会清空全部新增/修改状态 | 这是当前 Demo 的明确需求；正式产品需要服务端持久化、版本快照及可追溯操作记录 |
